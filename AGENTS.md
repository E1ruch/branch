# Команда разработки «Ветки»

«Ветка» — iOS-приложение сообществ. Начинай с затронутого кода и тестов. Сверяй архитектурные решения с `docs/architecture.md`, интерфейс с `docs/design-system.md`, локальный запуск с `docs/handoff.md`.

## Роли

| Кто | За что отвечает |
| --- | --- |
| Основной агент Codex | Уточняет критерии приёмки из запроса, распределяет задачи, согласует контракт iOS ↔ API, проверяет общий diff и собирает итог. |
| `vetka_ios` | Swift 6, iOS 17+, модули `ios/Packages/VetkaKit`, клиентский контракт, интерфейс и тесты iOS. |
| `vetka_backend` | Go API, воркер, PostgreSQL, Redis, миграции, серверные тесты и локальный Docker Compose. |
| `vetka_qa` | Независимая проверка diff, регрессий, API-контракта и затронутых сценариев на симуляторе. Работает без правок. |

## Работа над задачей

1. При запросе на работу командой назначь нужных агентов. Если именные профили недоступны, передай обычным подагентам обязанности из таблицы и границы задачи.
2. Для изменения API согласуй путь и метод, поля JSON, ошибки, авторизацию и совместимость с установленными версиями клиента до параллельной реализации. Сверь Go-обработчик с `Networking/API.swift` и моделями `Core`.
3. Разделяй правки по файлам между разработчиками. Для зависимых изменений задай порядок. Если в задаче нужен независимый контроль, передай `vetka_qa` готовый diff и критерии приёмки.
4. Проверь итоговый diff и сообщи, что проверено и что осталось непроверенным. Обсуждай результат по-русски. Коммить и пушь только по прямому запросу пользователя.

## Проверки

- Бэкенд. Из `backend/` запускай `make test` и `make vet` сообразно изменению. Интеграционным тестам нужен локальный PostgreSQL, который указан в `TEST_DATABASE_URL`. Перед сквозной проверкой убедись, что `/readyz` возвращает 200. Для проверки счётчиков голосов и «горячего» запусти воркер.
- Пакет iOS. Из `ios/Packages/VetkaKit` используй `xcodebuild test -scheme VetkaKit -destination 'platform=iOS Simulator,name=iPhone 16 Pro'` или подставь доступный симулятор. Если выбран Command Line Tools, укажи `DEVELOPER_DIR` полного Xcode.
- Приложение iOS. Используй `ios/branch.xcodeproj`, схему `branch` и подходящие `branchUITests`. Сквозные UI-тесты с API используют `VETKA_UI_TEST_API_URL` (по умолчанию `http://localhost:8080`). Для изменений интерфейса проверь затронутые состояния в светлой и тёмной темах, включая навигацию и жесты, если они затронуты.
