# Ветка — передача контекста в новый чат

Прочитай этот файл целиком, затем `docs/architecture.md` (архитектура и все
ключевые решения) и `docs/design-system.md` (дизайн-система — источник правды
по цветам и UX). Код — главный источник правды; здесь то, чего в коде не видно.

## Проект

«Ветка» — iOS-приложение сообществ для СНГ (гибрид Reddit и Пикабу). Хобби-проект,
но архитектура должна выдерживать рост. Монорепо:

- `backend/` — Go 1.26+ (chi, pgx без ORM, goose), PostgreSQL 16, Redis 7.
  `cmd/api` (HTTP), `cmd/worker` (сбрасывает голоса в счётчики), `cmd/migrate`.
- `ios/` — `branch.xcodeproj` (тонкий app-таргет `VetkaApp.swift`) + локальный
  SPM-пакет `ios/Packages/VetkaKit` (Swift 6, strict concurrency, iOS 17):
  `Core`, `Networking`, `Session`, `DesignSystem`, `Stores`, `FeedUI` (общая
  лента и пейджер с шапкой), `AuthFeature`, `CommunitiesFeature`,
  `SearchFeature`, `FeedFeature`, `PostFeature`, `ComposeFeature`, `AppFeature`.
- `infra/docker-compose.yml` — Postgres и Redis.

Приоритеты (не обсуждаются): плавность уровня Telegram (ничего тяжёлого в main,
оптимистичный UI, skeleton вместо спиннеров), жесты и haptics, чистый UI.

## Как работать с пользователем

- Общение по-русски, коротко, объяснять только ключевые решения.
- Модули — по одному; после модуля ждать «дальше» (или выбора следующего шага).
- **Коммитить только когда пользователь просит** («Сделай коммит…»). Перед
  коммитом смотреть `git status`: однажды `git add -A` захватил локальную схему
  Xcode с IP Mac'а — теперь она в `.gitignore`. В конце сообщения коммита строка
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Ничего не пушить.
- Пользователь часто присылает скриншоты-референсы (Telegram) — повторять
  вид и поведение, анимации проверять видео (см. «Грабли»).
- Проверять вживую: тесты + запуск (бэкенд — curl/смоук, iOS — симулятор и
  скриншоты). Честно говорить, что не проверено.
- Пользователь тестирует и на своём iPhone. Платной команды Apple нет →
  Sign in with Apple скрыт флагом `AppEnvironment.Features.signInWithApple`,
  entitlement отвязан (как включить — в комментарии у флага).
- Решения пользователя по дизайну: цвета — по `docs/design-system.md`;
  основные кнопки — белый текст на `#119B82` (в тёмной теме `#092B23` на
  `#20C997`); где пара не проходит WCAG, брать ближайший тёмный оттенок того
  же тона (все такие места подписаны в `Palette.swift`).

## Запуск локально

```bash
cd backend
make infra-up      # Postgres + Redis в Docker (Docker пользователь запускает сам)
make migrate       # применено 00001–00014
make run           # API на :8080 (слушает все интерфейсы)
make worker        # обязателен: без него счёт и «горячее» не двигаются
make test          # TEST_DATABASE_URL уже задан в Makefile; каждый тест — своя БД
```

- `backend/.env` — локальный (в `.gitignore`): постоянный `JWT_SIGNING_KEY`
  уже вписан. Telegram выключен; для локального Telegram-входа есть
  `TELEGRAM_FAKE_LOGIN=true` + любые `TELEGRAM_BOT_TOKEN/USERNAME` (см.
  `.env.example`; с https в `PUBLIC_BASE_URL` сервер не стартует).
- Вход в приложение локально — по нику и паролю (регистрация в приложении).
  В базе есть тестовые пользователи `live_test`, `live_voter`, `dev`, `dev2`
  (пароли у `dev*` знает пользователь), ~70 постов и 13 сообществ.
- API и воркер запускать во вкладках терминала пользователя (`make run`,
  `make worker` в `backend/`). Вкладки иногда закрываются сами (перезапуск
  приложения) — тогда приложение молча «не грузит ленту»: первым делом
  `curl localhost:8080/healthz`. На 29.10 (вечер) API (`:8080`) и воркер с
  текущим кодом запущены во вкладках панели терминала «api» и «worker»,
  которые открыл Claude: их можно остановить (`stop_terminal_tab`) и
  перезапустить без пользователя.
  Если Docker не запущен (после перезагрузки Mac), API падает с
  `connection refused` на 5432 — попросить пользователя запустить Docker.

### iOS

- `xcode-select` указывает на Command Line Tools — **каждой** команде
  `xcodebuild`/`xcrun` передавать
  `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`
  (или попросить пользователя сделать `sudo xcode-select -s …`; без этого не
  работает и панель симулятора Claude).
- Тесты пакета: `cd ios/Packages/VetkaKit && xcodebuild test -scheme VetkaKit
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro'` (102 теста, Swift Testing).
- Приложение и UI-тесты: `cd ios && xcodebuild test -project branch.xcodeproj
  -scheme branch -destination 'platform=iOS Simulator,name=iPhone 16 Pro'
  -parallel-testing-enabled NO -only-testing:branchUITests/branchUITests/…`.
  Скриншоты из UI-тестов: `xcrun xcresulttool export attachments --path X.xcresult --output-path DIR`.
- Тапать в симуляторе через `simctl` нельзя — для проверки UI писать XCUITest
  или снимать `xcrun simctl io <device> screenshot`. Тёмная тема:
  `xcrun simctl ui <device> appearance dark`.
- Телефон: в схеме Xcode `VETKA_API_URL=http://<IP Mac>:8080` (IP меняется:
  на 29.10 — `192.168.31.37`, смотреть `ipconfig getifaddr en0`);
  debug-сборка запоминает адрес; нужно разрешение «Локальная сеть».
- Симулятор тоже запоминает адрес: если лента «не загрузилась», а API жив —
  `SIMCTL_CHILD_VETKA_API_URL=http://localhost:8080 xcrun simctl launch booted laviosa.branch`.
- Панель симулятора Claude работает (тапы, ввод, скриншоты), но скриншот
  отстаёт от экрана — после действия ждать ~2 с. Кириллицу её ввод портит
  (ввод идёт через буфер обмена в другой кодировке), а латиница на русской
  раскладке превращается в «Пкуфе». Обход: печатать латиницей по раскладке
  ЙЦУКЕН («Ntcnjdsq gjcn» → «Тестовый пост»), отдельные буквы иногда теряются.
  Тап короче ~0.15 с по ячейке иногда не срабатывает. Если пользователь в
  это время сам трогает симулятор — не мешать (было: правил свой черновик).
- Экранная клавиатура в симуляторе обычно скрыта (подключена аппаратная):
  `set_keyboard show` панели помогает не всегда. Аппаратный Return в
  SwiftUI `TextField(axis: .vertical)` **отправляет поле** (`onSubmit`), а не
  вставляет перенос. `select_all` недоступен при русской раскладке.

## Что сделано (по коммитам)

Бэкенд (всё под `/v1`, ошибки `{"error":{"code","message","field"}}`, курсоры непрозрачные, списки `{items, next_cursor}`):

- Авторизация: ник+пароль (argon2id, лимиты попыток), Apple (JWKS, nonce),
  Telegram (HMAC, анти-replay, фейковый локальный вход); access JWT Ed25519 15 мин
  + refresh с ротацией и детектом кражи (grace 30 с).
- Профиль: `/me` (GET/PATCH/DELETE), `/users/{username}` (+`/posts`, `/comments`),
  проверка ника; первая смена ника бесплатна, дальше раз в 30 дней; удаление аккаунта.
  Подписки на людей (миграция 00012): `user_follows`, у `users` —
  `posts_count`, `followers_count`, `following_count` (ведут триггеры:
  посты — на вставку и мягкое удаление), `PUT|DELETE
  /users/{username}/follow` (состояние, отдаёт профиль), `is_following` в
  `/users/{username}`; удаление аккаунта снимает подписки в обе стороны.
- Сообщества: создание (3 в сутки), правка модераторами, подписка PUT/DELETE,
  популярные, trigram-поиск, мои подписки. NSFW скрыт из дискавери.
- Посты и ленты: hot/new общая, по сообществу, подписки (LATERAL); превью 600 символов.
- Голоса: PUT состояния (−1/0/1), outbox `vote_deltas` + воркер, карма.
- Комментарии: дерево (топ-8 ответов на родителя, 5 уровней, лимит 400),
  заглушки `more`/`continue`, надгробия, голоса за комментарии. Длина —
  до 4000 символов (сервис; CHECK в базе остался 10000 как страховка),
  правка — 30 за 10 минут, та же строка не ставит «изменено».

iOS:

- Сеть (`Endpoint<Response>`, `APIClient`, каталог `API`), сессия (Keychain,
  актор `TokenStore` с единым refresh), роутер с отдельным стеком на вкладку и deep links.
- Вход/регистрация по паролю, онбординг с живой проверкой ника.
- Лента на `UICollectionView` (PostLayout считается вне main, ячейки без
  Auto Layout), три ленты в контейнере, оптимистичные голоса с дебаунсом 300 мс,
  свайпы вправо/влево = за/против, контекстное меню, «⋯», поделиться.
- Редизайн шаг 1: токены `Palette`, 5 вкладок (Лента, Поиск, «+», Активность,
  Профиль; с шага 4 вместо «Активности» — «Сообщества», а «Активность»
  открывается колокольчиком в шапке ленты рядом с лупой, `Route.activity`), шапка ленты с логотипом и «пилюлями», поиск сообществ.
- Шаг 2, экран поста (`PostFeature`, `Route.post` и `Route.commentThread`):
  пост целиком (из ленты — мгновенно по превью, потом полный текст), дерево
  плоским списком на `UICollectionView` с линиями веток (раскладки вне main),
  голоса за пост и комментарии, поле ввода на месте таб-бара (keyboardLayoutGuide),
  «Ответить», оптимистичная отправка (временный отрицательный id, при ошибке
  текст возвращается в поле), сворачивание веток тапом, контекстное меню
  («К родительскому», копировать, автор), «Ещё N ответов» на месте, экран
  ветки («Весь пост», «Выше»), сортировка «Лучшие/Новые».
- `Stores`: общий `PostStore` (identity map, ленты и экран поста читают посты
  из него) и `VoteSync` (оптимистичные голоса для постов и комментариев).
  `VoteControl` переехал в DesignSystem. Бэкенд: `GET /v1/comments/{id}`.
- Шаг 3, создание поста (`ComposeFeature`, лист по «+»): выбор сообщества
  (подписки → популярные, поиск), заголовок (Return переводит в текст),
  текст, 18+ (принудительно в 18+-сообществе), черновик сохраняется сам на
  аккаунт (UserDefaults), «Сохранить/Удалить черновик» по «Отмена»,
  публикация — компактная круглая кнопка; после неё лист закрывается и
  открывается пост (в `onDismiss`, не раньше). Ошибки — текстом внизу.
- Истории (предложение пользователя): посты автора связываются в части.
  Бэкенд: таблица `stories` (миграция 00008), `posts.story_id/story_part`,
  `continues_post_id` при создании (только свой пост, часть — в конец,
  блокировки строк от гонки), `story: {id, part, parts}` в каждом посте
  (номер по живым частям), `GET /v1/posts/{id}/story` — оглавление.
  iOS: чип «Продолжение истории» в «+» (список своих постов), «Добавить
  следующую часть» в «⋯» поста, строка «‹ История · Часть 2 из 3 ›» под
  постом (середина — оглавление, «+» у автора на последней части), метка
  «Часть 2 из 3» в ленте.
- Шапка поста как в ленте: автор сверху, «время · сообщество» под ним.
- `CFBundleLocalizations = ru` в Info.plist: системные строки по-русски.
- Плавность: таб-бар на экране поста не прячется (поле ввода над ним),
  заголовок поста известен до push (берётся из стора) и въезжает с анимацией,
  тап по треду при открытой клавиатуре только прячет её.
- Экран создания поста (переделан по просьбе пользователя, в духе Telegram
  «Новый канал»): заголовок в скруглённом поле (до 3 строк, крестик очистки),
  текст в таком же поле — **WYSIWYG-редактор** на `UITextView`
  (`MarkdownTextView`): форматирование видно сразу, без `**`/`#`. Применяется
  через меню выделения «Форматирование» (Жирный, Курсив, Зачёркнутый,
  Моноширинный, Ссылка с вводом адреса; Подзаголовок, Цитата, Список;
  «Обычный текст»), галочки у применённого, повтор — снимает. Список: «• »,
  Return продолжает, на пустом пункте заканчивает. Смысл хранится в
  атрибутах `.md*`, вид выводится из них (`MarkdownStyler`); в черновик и на
  сервер уходит markdown (`MarkdownCodec`, туда-обратно, с экранированием
  `\*` и т.п. — тесты `MarkdownCodecTests`). Скрепка (меню «Фото/Видео —
  скоро») — круглая кнопка слева от счётчика «N / 40 000». Тап в пустое место
  прячет клавиатуру. Сообщество/история/18+ — в листе «Настройки
  публикации» (`PublishSettingsView`, открывается подзаголовком под «Новый
  пост»; публикация без сообщества сама открывает его). Черновик без
  загруженного профиля пишется под последний известный аккаунт.
- Поиск по макету пользователя (`SearchFeature`, вкладка «Поиск»): поле в
  навбаре (лупа в ленте открывает вкладку и ставит фокус), фильтры «Всё /
  Сообщества / Пользователи / Посты», пока поле пустое — «Популярные
  запросы» (чипы) и «Недавние» (открытое из поиска, на устройстве, на
  аккаунт, 10 штук, «Очистить»). Под «Всё» по 3 в разделе и «Все N».
  Бэкенд: `GET /v1/search/users`, `/v1/search/posts` (одна страница,
  ближайшие по заголовку, без NSFW), `/v1/search/popular`, `POST
  /v1/search/queries` (миграция 00010). Популярные — запросы, которые за
  неделю искали ≥3 разных человека (считаются только «осмысленные»:
  Return, тап по результату или чипу, только со входом), добивается
  названиями крупных сообществ. Потом поиск разобран под нагрузку (цифры и
  решения — в architecture.md, «Поиск»): посты по «горячести», люди —
  ник по началу + имя, от 3 букв, популярные считает воркер раз в 10 минут,
  лимит 90 запросов в минуту.
- Поле поиска как в Telegram (`SearchBar` в DesignSystem) вместо системного
  `.searchable` везде: «Поиск», «Сообщества», выбор сообщества в «+». В покое
  серая капсула с подсказкой по центру; по тапу светлеет и поднимается
  (тень; в тёмной теме — светлее фон), подсказка уезжает влево, справа
  выезжает круглая ✕ (очистить + убрать клавиатуру). Пружина 0,4 с,
  с Reduce Motion — короткий fade. На вкладке «Поиск» навбар скрыт: поле
  на его месте, как в макете. Фокус держит экран (`FocusState`).
- Кнопка «назад» — круглая (`BackButton` + `.vetkaBackButton()` в
  DesignSystem) на всех экранах из `RouteView` и в листе настроек
  публикации. Системная кнопка спрятана, свайп назад возвращён расширением
  `UINavigationController` (делегат `interactivePopGestureRecognizer`,
  только при `viewControllers.count > 1`); UI-тест back-swipe это проверяет.
  Кнопка 38 pt: навбар 44 pt обрезает всё, что за ним, тени тоже.
- Шаг 4, часть 1 — сообщества. Бэкенд: правила (`communities.rules jsonb`,
  миграция 00009, PATCH `rules` заменяет список, отдаются только в одиночном
  сообществе). iOS: новый модуль `FeedUI` (лента вынесена из `FeedFeature`,
  источник страниц — `FeedSource`; `HeaderPagerViewController` — шапка +
  вкладки поверх страниц), `CommunityStore` в `Stores` (оптимистичная
  подписка), страница сообщества (`CommunityScreen`: шапка, «Лента» = new,
  «Популярное» = hot, «Правила»; кнопка «Написать пост» открывает «+» с этим
  сообществом), экран сообществ переехал во вкладку «Сообщества»: под поиском по центру вкладки
  «Популярное» и «Подписки» со счётчиками в кружках («25+», пока есть ещё
  страницы — общего числа сервер не отдаёт), кнопка в строке: зелёная
  «Подписаться» / серая «Отписаться» (так же в шапке сообщества). Отписка во
  вкладке «Подписки» не убирает строку до следующей загрузки — ошибку можно
  отменить одним тапом. Локально у `kotiki` и `yumor` вписаны тестовые правила.
- Шаг 4, часть 2 — профиль (решения пользователя: в шапке «публикации ·
  карма · подписки · подписчики», вкладки «Комментарии» нет, подписки на
  людей — да). Модуль `ProfileFeature`: `ProfileScreen` один для своего
  (вкладка «Профиль», корень стека) и чужого (`Route.user`; на себя — без
  кнопки). Шапка `ProfileHeaderView` (UIKit, по центру): аватар 88 по нику,
  имя, «@ник · на Ветке с <месяц год>», «О себе», четыре `StatView`,
  кнопка «Подписаться»/«Отписаться» как у сообществ. Карма — одно число
  (сумма), тап — меню с разбивкой «За посты / За комментарии». Ник известен
  до загрузки (это маршрут) → аватар и @ник с первого кадра, остальное —
  скелетоны; свой профиль кладётся в стор из `/me` (`seedMyProfile` в
  `AppRootView`) — без скелетона. Профиль перезагружается при каждом показе
  (`.task`). `HeaderPagerViewController` с одной страницей не показывает
  вкладки (только линия). `ProfileStore` в `Stores` — оптимистичная
  подписка по образцу `CommunityStore` (дебаунс 300 мс, откат), заодно
  двигает «подписки» в вашем профиле. Модели: `Profile` (+`is_following`),
  у `User`/`Me` — счётчики.
- Меню по долгому нажатию «как в Telegram» — `ActionMenu` в DesignSystem
  (своё, не системный UIContextMenu): экран размывается, элемент
  поднимается снимком (не сжимается в превью; во всю ширину — чуть
  уменьшается), над ним капсула голосов ↑ счёт ↓ (вместо реакций; голос
  закрывает меню), под ним карточка с группами, «Удалить» красным; низкий
  элемент сдвигается вверх, слишком высокий показывается верхом. Палец,
  открывший меню, можно довести до пункта и отпустить (хост передаёт
  long press в `track`/`release`). Пункт выполняется после закрытия.
  Используется: долгое нажатие на пост в ленте и на комментарий, «⋯» поста
  в ленте (то же меню с подъёмом), «⋯» на экране поста — режим
  `present(fromButton:)`: карточка из кнопки, без подъёма. Плавность
  открытия и закрытия проверена по видео; тёмная тема не проверялась
  (в приложении выбрана «Светлая»).
- Настройки (по просьбе пользователя «как в Telegram»): модуль
  `SettingsFeature`, `Route.settings/.appearance/.editProfile`, вход —
  шестерёнка в своём профиле. «Настройки»: шапка (аватар, имя, @ник),

  — приложение в миниатюре скелетоном, цвета `Palette`, разрешённые под
  тему) + переключатель «Как в системе» (по умолчанию). Тема —
  `ThemeStore` в DesignSystem: `overrideUserInterfaceStyle` окна (не
  `preferredColorScheme`), ставится до первого кадра (`ThemeWindowHook`),
  смена — круговое раскрытие от пальца (снимок окна с маской-дыркой,

  остаток символов — у самого лимита; ник заблокирован до
  `username_changeable_at`. Живая проверка ника вынесена в
  `Stores/UsernameCheck` (онбординг тоже на ней), `UsernameRule` — в `Core`.

## Грабли, на которые уже наступили

- Swift 6.1: в `Task {}` нет вывода типизированных ошибок — писать
  `do throws(APIError) { … } catch { switch error … }`.
- Вложенный тип `Body` внутри `ButtonStyle` конфликтует с ассоциированным типом.
- В `project.pbxproj` у `XCSwiftPackageProductDependency` локального пакета
  обязателен `package = <XCLocalSwiftPackageReference>`. Правки pbxproj делать
  скриптом и проверять `plutil -lint` + сборкой. Новые модули пакета Xcode у
  пользователя иногда не видит — помогает Reset Package Caches / чистка DerivedData.
- Swift Testing: `#expect` внутри обработчика `URLProtocol` роняет процесс —
  только записывать запросы, проверять в теле теста.
- XCUITest не может ввести латиницу в `SecureField` при русской клавиатуре
  симулятора (поэтому нет UI-теста входа). Системный алерт «Открыть в
  приложении?» при deep link нужно подтверждать через springboard.
- В macOS нет `timeout`; zsh не разбивает `$VAR` с пробелами на слова — для
  команд с аргументами использовать функции.
- Даты от Go: RFC 3339 с дробью и без — `JSON.decoder()` понимает оба.
- Миграции: уже применённые не редактировать, только новые файлы.
- **Тесты бэкенда — только `make test`**: голый `go test ./...` не видит
  `TEST_DATABASE_URL` и молча *пропускает* все тесты с базой (SKIP, а итог —
  `ok`). Так однажды прошла сломанная SQL.
- **Счётчики через строчный триггер + массовый DELETE = квадратичное
  время**: одна и та же строка `users` переписывается N раз в одной
  транзакции. Удаление аккаунта со 100k подписчиков шло 3,5 мин (таймаут
  API 10 с). Поэтому счётчики подписок — триггер на запрос с transition
  table (миграция 00014, 2,6 с на 100k). Счётчик постов строчный
  (UPDATE-триггер на запрос нельзя ограничить колонками) — массовое
  удаление постов пусть пересчитывает `posts_count` само. Подписки:
  лимит 60 в минуту и 400 в сутки на аккаунт (`limitFollows`). Предел
  «вирусного» человека: ~400 подписок/с на одного (одна строка-счётчик);
  дальше — счётчики через outbox и воркер, как голоса.
- Нагрузку поиска проверять на отдельной базе: `CREATE DATABASE vetka_bench`,
  `DATABASE_URL=…/vetka_bench go run ./cmd/migrate up`, данные через
  `generate_series` (функция, вызываемая на каждую строку, — иначе Postgres
  посчитает подзапрос один раз и все строки выйдут одинаковыми), затем
  `EXPLAIN ANALYZE` тех же запросов; базу потом удалить.
- **TabView и «+»**: нельзя давать TabView выбирать вкладку-кнопку даже на
  миг (биндинг отказывает) — стек ленты переподключается, и экраны, открытые
  после, остаются без safe area (под навбаром). Поэтому поверх центральной
  кнопки лежит настоящая кнопка (`AppRootView`).
- **Не прятать таб-бар** через `.toolbar(.hidden, for: .tabBar)`: при
  возврате назад SwiftUI показывает его через ~0.6 с после анимации (видно
  по кадрам). Экран поста держит таб-бар, поле ввода стоит над ним.
- Плавность проверять видео, не скриншотами: `xcrun simctl io booted
  recordVideo`, кадры — AVAssetImageGenerator (ffmpeg нет).
- Push сразу после закрытия листа делать в `onDismiss`.
- `@FocusState` после pop внутри листа не восстанавливается (пробовал
  задержку и `onAppear`) — не тратить время.
- `plutil -insert` переписывает plist и выкидывает комментарии — править руками.
- Закрывающийся лист вызывает `onDisappear` → `saveNow()`: после публикации
  черновик не должен сохраняться (флаг `isPublished` в `ComposeModel`).
- В тестах `Testing` экспортирует свой `Comment` — писать `Core.Comment`.
- `async let` с typed throws теряет тип ошибки: параллельные запросы в
  `ThreadModel` возвращают `Result` через хелпер `result {}`.
- `make run` из песочницы Claude работает, но надёжнее запускать API и
  воркер во вкладках терминала пользователя.
- Локальные тестовые данные: пользователь `thread_bot` и глубокая ветка под
  постом 27 («Собрал первую клавиатуру») — для проверки `more`/`continue`.
  У `dev` есть история из 2 частей («Ремонт старой «Нивы»…» → «Часть
  четвертая», «Музыка») и тестовые посты в «Живых постах». В симуляторе у
  `dev` лежит **черновик пользователя** (заголовок про «медвежьи какашки») —
  не удалять.
- **Фокус между SwiftUI-полем и `UITextView`**: не менять `@FocusState`
  заголовка вручную при переходе в текст — SwiftUI потом снимает первого
  респондера, и клавиатура уходит. Переход делать прямым
  `becomeFirstResponder` (`MarkdownEditor.focus()`); заголовок отпустит фокус сам.
- `UITextView` в SwiftUI: высота — через `sizeThatFits(_:uiView:context:)`;
  «умную» вставку (`smartInsertDeleteType`) выключать — она добавляет пробелы
  и ломает разметку. Атрибуты меняются в `textStorage` без отмены (undo
  только для набранного текста).
- **Таб-бар над пейджером**: с несколькими списками система не понимает, какой
  скроллится под таб-баром, и оставляет его прозрачным — на таких экранах
  `.toolbarBackground(.visible, for: .tabBar)`. Навбар там же прозрачен
  (SwiftUI-скролла нет) и показывает фон экрана — фон экрана `surface`, как у шапки.
- Аватар-инициал сообщества — всегда по `title` (как в списках), не по slug,
  иначе у одного сообщества разные цвета.
- Строка `List` со своей кнопкой: `NavigationLink` кладётся в `.background`
  с `opacity(0)` — строка открывается тапом, кнопка жмётся отдельно, шеврон
  не съедает место.
- Из песочницы Claude нельзя остановить чужой `make run` — для проверки новой
  версии API Claude поднимает вторую копию **`make run HTTP_ADDR=:8081`** (именно
  через make: он подхватывает `.env` с `JWT_SIGNING_KEY`; голый `go run`
  берёт случайный ключ, приложение получает 401 и **выходит из аккаунта**)
  и запускает симулятор с `SIMCTL_CHILD_VETKA_API_URL=http://localhost:8081`
  (потом вернуть на 8080).
- Своя картинка системной кнопки «назад» (`setBackIndicatorImage`) не
  годится: UIKit её сжимает и сдвигает, а `.toolbarBackground` на экране
  сбрасывает её к системной.
- Плавность по видео: `simctl io recordVideo` сам изредка дублирует
  кадры (в обычной ленте ~2 на 115) — сравнивать с лентой тем же жестом,
  прежде чем искать рывок. Кадры и контакт-листы удобно делать маленькими
  Swift-скриптами в scratchpad (AVAssetImageGenerator → JPEG; разница
  соседних кадров в уменьшенном сером виде находит движение). Удалять
  файлы через `rm` с относительной маской песочница не даёт — писать в
  новую папку.
- Пользователь параллельно трогает симулятор: «лишние» действия в записи
  (переключение темы, подписка) могут быть его — не принимать за баг сразу.
- Тап панели симулятора во время анимации push/pop теряется — ждать ~1,5 с.
- Отладка: бывает быстрее временно залогировать стек (`Thread.callStackSymbols`
  в `os.Logger`) и прочитать `xcrun simctl spawn booted log show --predicate
  'subsystem == "vetka"'`, чем гадать.
