# Ревью входа по email и выбора ника

Регистрация в «Ветке» состоит из двух шагов. Сначала пользователь создаёт аккаунт по email и паролю, затем выбирает публичный ник. Повторный вход открывает онбординг, если этот шаг ещё не завершён.

## Контракт и хранение

| Запрос | Результат |
| --- | --- |
| `POST /v1/auth/register` с `email`, `password`, необязательным `device_name` | `201`, токены, `is_new_user: true` и пустой `user.username`. Повторный адрес даёт `409 email_taken`. Ошибки полей дают `422 validation_failed`. |
| `POST /v1/auth/login` с теми же полями | `200`, токены и текущий ник. Неизвестный email и неверный пароль дают `401 invalid_credentials`. |
| `GET /v1/usernames/{name}/availability` | `200` с `available`, а для недоступного ника также `reason` (`taken` или `invalid`). |
| `PATCH /v1/me` с `username` | `200` и сохранённый ник. Если ник успели занять, сервер возвращает `409 username_taken`. Социальные записи до выбора ника получают `403 username_required`. |

Миграция `00015` добавляет уникальный `password_credentials.email` и разрешает `NULL` в `users.username` на время онбординга. Email очищается от внешних пробелов и приводится к нижнему регистру. Redis получает хеш нормализованного адреса для лимита входа, а публичные DTO содержат только ник. Удаление аккаунта удаляет парольную запись вместе с email. Профили и хеши паролей старых аккаунтов сохраняются. Для повторного входа в аккаунт, созданный только с ником, потребуется отдельная привязка email.

Откат SQL требует заполненных ников и удаляет сохранённые email. Для возврата старой версии после появления email-аккаунтов нужна резервная копия и отдельный план переноса. В локальном сценарии email служит идентификатором входа. Подтверждение владения адресом и восстановление пароля остаются условиями для публичного запуска.

## Что проверить в приложении

1. Переключить «Вход» и «Регистрация» с открытой клавиатурой. Проверить фокус и доступность кнопки. После регистрации переход к нику должен происходить прямо в том же окне.
2. Набрать слишком короткий ник, занятый ник и свободный ник. Проверить локальную подсказку, статус «Проверяем ник…», тексты о доступности и состояние «Продолжить». При быстром наборе ответ для предыдущего значения не должен менять статус нового.
3. Прервать выбор и запустить приложение снова. При доступном API оно восстанавливает шаг из `/v1/me`. Проверить также выход с экрана выбора, вход по email и завершение онбординга. После сохранения повторный вход должен сразу открыть приложение.
4. Проверить потерю сети во время запроса доступности, действие «Проверить ещё раз» и конфликт при сохранении, если другой аккаунт занял ник после проверки. При Reduce Motion переход к онбордингу использует затухание без сдвига.

## Результаты проверок

- `GOFLAGS=-p=1 make test` прошёл с `-race`. Покрыты регистрация и вход, два одновременных запроса на один email, лимиты, удаление аккаунта, блокировка социального действия до выбора ника и конфликт после успешной проверки доступности.
- В `VetkaKit` прошли 104 теста. Добавлены проверки ответа, запоздавшего после последовательности A → B → A, и повторной проверки ника после сетевой ошибки.
- Сквозной тест прошёл на iPhone 18 Pro Simulator. Он проверил регистрацию из формы, возврат к выбору ника после перезапуска и входа, занятый и свободный ники, сохранение, повторный вход через API с теми же данными и открытие готового профиля после перезапуска.
- На видео симулятора клавиатура закрывается при переходе к выбору ника и открывается с латинской раскладкой по нажатию на поле. При смене однострочных статусов кнопка «Продолжить» сохраняет положение. Замеры кадров на физическом iPhone входят в ручное ревью плавности.

## Точки для ревью кода

- Проверить атомарность регистрации в `backend/internal/auth/store.go` и конкурентное сохранение ника в `backend/internal/user/user.go`. Поздний конфликт в обоих случаях должен вернуть ошибку поля.
- Проверить в `backend/internal/httpapi/router.go`, что учётная запись без ника может прочитать свой профиль, выбрать ник, выйти и удалить аккаунт. Социальные действия требуют ник.
- Проверить в `UsernameCheck.swift` и `SessionStore.swift`, что запоздавший ответ не переоткрывает завершённый онбординг и не разрешает сохранение другого значения.

## Как воспроизвести проверки

В `backend/` запустить `make infra-up`, `make migrate` и `GOFLAGS=-p=1 make test`. Для проверки iOS запустить `make run` в отдельном терминале. Сценарий использует API на порту `8080` и симулятор без активного аккаунта. На новом симуляторе сначала закройте системную подсказку клавиатуры. Команда из `ios/` приведена ниже.

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild test \
  -project branch.xcodeproj -scheme branch \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' \
  -parallel-testing-enabled NO \
  -only-testing:branchUITests/branchUITests/testEmailRegistrationAndRequiredNickname
```
